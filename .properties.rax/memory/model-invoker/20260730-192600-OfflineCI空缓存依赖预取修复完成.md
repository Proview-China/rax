## 根因与修复

`go mod download` 在 clean runner 上不会下载依赖模块自身测试所需的传递模块。原脚本随即把外部代理指向关闭的 loopback 端口，后续 `go mod tidy -diff` 因尝试下载这些模块而失败。

依赖获取阶段现先执行一次 `go mod tidy -diff`，在仍允许访问 Go module proxy 时解析并缓存完整 tidy 图。脚本随后封网，并保留第二次 `go mod tidy -diff`、vet 和全部测试，从而验证执行阶段不依赖网络或预热缓存。

## 验证

- 修复脚本在相同空缓存下越过原失败点；基线 main 随后仅命中已知 Catalog Evidence 过期门。
